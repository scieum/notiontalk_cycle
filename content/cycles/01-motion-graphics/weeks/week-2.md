## 🎯 이번 주에 하는 것

1주차에는 영상마다 색, 글꼴, 속도가 조금씩 달라지고, 마음에 안 들어 다시 만드느라 토큰도 많이 들었죠. 이번 주에는 그 문제를 **하네스**로 묶어요.

**하네스 = 영상 만들 때마다 쓰는 기본 틀**이에요. 디자인, 모션, 작업 순서를 한 번 정해 두면 어떤 단원을 넣어도 **같은 디자인과 같은 모션**으로, **토큰을 낭비하지 않고** 영상이 나와요.

|  | 하네스 없이 | 하네스로 |
| --- | --- | --- |
| 디자인 | 영상마다 색, 글꼴, 글자 크기가 달라져요 | 항상 `design.md`, `video.md`대로 나와요 |
| 모션 | "부드럽게", "적당히"를 AI가 매번 다르게 해석해요 | `motion.md`의 숫자대로 같은 속도와 움직임이 나와요 |
| 토큰 | 다 만든 뒤 엎고, 같은 설명을 반복해요 | 장면표와 스냅보드를 먼저 승인하니까 엎는 일이 줄어요 |
| 수정 | 영상마다 같은 지적을 다시 해요 | 한 번 고친 건 규칙으로 남아요 |
| 다음 영상 | 처음부터 다시 설명해요 | "수업 영상 만들자"라고 하고 단원만 고르면 돼요 |

두 트랙 중 하나를 골라주세요.

## 📋 A · 처음 한 번 (준비)

복사해서 붙여 넣는 순서 그대로예요. **한 번에 한 프롬프트씩** 보내고, 결과를 확인한 뒤 다음으로 넘어가요.

```prompt ① 저장소 둘러보기
이 저장소를 둘러보고 폴더마다 무엇이 들어 있는지, 내가 앞으로 무엇을 만들어야 하는지 쉬운 말로 설명해줘. 아직 아무것도 만들지 마.
```

```prompt ② 교과서 넣기 (PDF 첨부)
첨부한 교과서 PDF를 docs/textbook/_format.md 형식에 맞춰 소단원별 md 파일로 바꿔줘.
- 본문 · 사료 · 표는 글자 하나도 바꾸지 말고, 문단마다 쪽수를 달아줘.
- 그림은 캡션과 쪽수만 적어줘.
- 다 만들면 docs/textbook/index.md에 목차를 채우고, 변환이 애매했던 곳을 목록으로 알려줘.
```

```prompt ③ motion.md 만들기 (레퍼런스 영상 첨부)
첨부한 영상을 레퍼런스로 docs/motion.md를 만들어줘.
- 먼저 영상의 움직임 성격을 세 가지 후보로 제안하고 나한테 고르게 해줘.
- 장 구성: 1 Primitives(Duration · Easing · Distance) / 2 Semantic(enter · exit · emphasis · transition · stagger) / 3 Pattern(src/parts 부품별) / 4 머무는 시간 / 5 카메라.
- 값마다 영상 몇 초에서 잰 값인지 출처를 달아줘. 잴 수 없으면 "레퍼런스(눈)"이라고 적어줘.
- 영상의 그림 · 글자 · 색은 가져오지 마.
```

```prompt ④ video.md 만들기
docs/video.md를 만들어줘. 교실 TV로 보는 수업 영상 기준이야.
나한테 세 가지만 물어봐: 배경 밝기 / 글자를 크게 채울지 여백을 둘지 / 마지막 정리 화면 모양. 질문마다 기본값을 줘.
장 구성: 1 글자 최소 크기 · 2 배경 · 3 글자 · 4 화면 틀 · 5 표기(교과서 표기 그대로) · 6 부품.
```

```prompt ⑤ 하네스 만들기
이 저장소에 수업 영상 하네스를 만들어줘.
- CLAUDE.md: 목적 / 규칙 3개(내용은 교과서에서만, 쪽수와 함께 · 값은 docs와 src/parts에서만 · 사람 승인 뒤에 만들고 critic이 판정) / 폴더 / 고정 · 참조 · 금지 / 작업 순서
- .claude/agents: content-editor(교과서 정리) · art-director(레퍼런스 정리) · director(장면표) · builder(HyperFrames 제작) · critic(판정만, 고치지 않음)
- .claude/skills/make-video: 브리프 → 교과서 정리 ✋ → 레퍼런스 → 장면표 ✋ → 스냅보드 ✋ → 생성 · 검수 → 렌더 → 규칙 남기기
만든 뒤 각 파일이 하는 일을 한 줄씩 알려줘.
```

```prompt ⑥ 점검
하네스를 점검해줘. 문서끼리 서로 다른 값이나 규칙이 있으면 찾아서 알려주고, 고치지는 마.
```

> 💡 ⑥을 꼭 해 주세요. 문서끼리 부딪치는 규칙을 영상 만들기 전에 미리 잡아 줘요. 리허설에서는 "글줄은 2줄까지" 규칙과 기사 조각 부품의 폭이 서로 맞지 않는 게 여기서 걸렸어요.

```more 하네스를 만들면 생기는 폴더와 역할
    notiontalk_cycle_harness/
    ├─ docs/
    │  ├─ design.md          ← 받은 재료
    │  ├─ textbook/          ← ② 단원별 .md + index.md 목차
    │  ├─ motion.md          ← ③
    │  └─ video.md           ← ④
    ├─ src/parts/            ← 받은 재료: 부품 7종
    ├─ CLAUDE.md             ← ⑤ 꼭 지킬 규칙
    ├─ .claude/agents/       ← ⑤ 역할 5개
    ├─ .claude/skills/make-video/  ← ⑤ 작업 순서
    └─ out/<영상이름>/        ← 영상마다: 브리프 · 교과서 정리 · 장면표 · 스냅보드 · gates.md · mp4

#### 역할 5개

| 에이전트 | 하는 일 |
| --- | --- |
| content-editor | 고른 단원에서 개념·용어·수치를 **쪽수와 함께** 정리해요 |
| art-director | 레퍼런스에서 구성·전환·박자를 정리해요 |
| director | 장면표를 짜요 |
| builder | 승인된 장면표대로 HyperFrames로 만들어요 |
| critic | 교과서와 기준 문서에 맞는지 **판정만** 해요. 고치지 않아요 |
```

## ⚠️ 자주 묻는 질문

### 왜 교과서를 .md로 바꿔 두나요?

영상을 만들 때마다 PDF 전체를 다시 읽으면 시간과 토큰이 많이 들어요. 단원별 .md로 한 번 나눠 두면 그 단원 파일만 읽으면 돼요. 쪽수가 붙어 있어서 critic이 "교과서에 없는 내용"을 잡아낼 수도 있어요.

### 스캔본 PDF도 되나요?

글자가 이미지로 된 스캔본은 느리고 부정확할 수 있어요. 글자를 드래그해서 선택할 수 있는 PDF가 가장 잘 돼요. ②에서 "변환이 애매했던 곳"으로 알려 준 쪽만 직접 확인해요.

### 승인할 때 무엇을 봐야 해요?

- **교과서 정리**: 교과서 내용이 맞는지, 빠진 핵심 개념은 없는지 봐요. 여기서 틀리면 나중에 고치는 비용이 가장 커요.
- **장면표**: 장면마다 무엇이 움직여서 개념을 보여주는지 봐요.
- **스냅보드**: 글자가 뒷자리에서도 읽히는지, 색과 글꼴이 `design.md`대로인지 봐요.

### 카드만 나타났다 사라지는 PPT 같아요

장면표를 승인할 때 "이 장면은 무엇이 움직여서 개념을 보여주나?"를 물어보고, 도식 중심으로 다시 짜 달라고 해요. 예를 들어 "응결"이라는 글자 대신 수증기 입자가 느려지며 모여 물방울이 되는 장면이에요.
